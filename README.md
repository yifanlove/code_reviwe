# 客服 FAQ 自动分类 — 提示词优化项目

## 项目概述

对 `task1_classifier.py` 中 `classify_question` 方法进行提示词工程优化，提升客服问题分类准确率。

---

## 改进思路

整个优化过程分为三个迭代阶段：

### 阶段一：提示词结构化改造（v1.0 → v2.0）

| 改进项 | 改进前 | 改进后 |
|--------|--------|--------|
| 角色设定 | 混在 user message 中，无 system role | 独立 `system` role，明确角色身份 |
| 分类定义 | 仅列出类别名称 | 完整的分类定义表（含定义 + 典型场景） |
| Few-Shot | 无 | 每类别 2 条，共 12 条示例 |
| 输出校验 | 无 | 结果必须在 6 个有效类别中，否则重试（最多 5 次） |
| 配置管理 | 硬编码在 Python 中 | 抽离到 `task1_prompts.yaml`，支持版本管理 |

### 阶段二：边界情况修复（v2.0 → v2.1）

- 新增 2 条分类规则：覆盖"提及业务名词但实质是投诉"的边界场景
- 新增 3 条 Few-Shot 示例：包含 id=23 误分类案例的纠正示例和对比示例
- 构造正反对比例：`"我想退货，请问怎么操作"` vs `"退货流程太麻烦"` 让模型学会区分

### 核心设计原则

1. **System / User 角色分离** — system 承载角色和规则，user 只传待分类问题
2. **Few-Shot 覆盖边界** — 每个类别 2+ 条示例，重点覆盖易混淆的边界 case
3. **验证 + 纠错闭环** — 输出不在有效集合时，将错误结果代入对话历史重试
4. **配置与代码分离** — YAML 管理提示词，修改无需动代码

## 发现的问题

### 问题 1：提示词指令与数据混在一起（v1.0）

- **现象**：分类指令、类别定义、用户问题全部写在一条 user message 中
- **影响**：模型对指令的遵循度不稳定，长 prompt 末尾的指令容易被稀释
- **修复**：将角色设定、规则、Few-Shot 写入 `system` role，user message 只包含待分类问题

### 问题 2：缺少 Few-Shot 示例（v1.0）

- **现象**：仅靠类别名称和一句话定义进行分类，模型缺乏参考基准
- **影响**：对模糊 / 跨类别问题容易误判
- **修复**：基于 `task1_categories.md` 的定义，为每个类别编写 2 条 Few-Shot 示例

### 问题 3：无输出校验机制（v1.0）

- **现象**：模型偶尔返回非标准类别的文本（如带解释、"退款/退货" 等变体写法）
- **影响**：下游系统收到不可识别的分类结果
- **修复**：增加白名单校验 + 最多 5 次重试，超限兜底返回"其他"

### 问题 4：关键词误导导致边界误判 — id=23（v2.0）

- **案例**：`"你们这个退货流程也太麻烦了吧，我都搞不懂怎么操作"`
- **原结果**：`退款退货` ❌ — 被关键词"退货"误导
- **正确结果**：`投诉建议` ✅ — 核心诉求是抱怨流程复杂度
- **根因**：提示词缺少"提及业务名词但实质是投诉"类边界情况的规则和示例
- **修复**：新增规则 4/5 + 正反对比 Few-Shot 示例

## AI 工具使用情况

| 工具 | 用途 | 说明 |
|------|------|------|
| **Claude Code** | 代码编辑、文件管理、配置抽离 | 完成 `task1_classifier.py` 的全部修改和 `task1_prompts.yaml` 的创建与迭代；通过 `Edit`/`Write` 工具精确修改代码 |
| **DeepSeek V4 Flash** | 分类推理 | 通过 API 调用，作为分类模型执行 30 条测试样本的推理 |
| **Claude Code（分析）** | 结果对比、问题诊断 | 对比 `result.json` 与 `fixed_result.json`，定位 id=23 误分类根因 |

### 协作流程

```
Claude Code                    DeepSeek V4 Flash
    │                                │
    ├─ 编写提示词 ──────────────────→│
    │                                ├─ 执行分类推理
    │←───────────────── 返回结果 ────┤
    │                                │
    ├─ 校验结果准确性                │
    ├─ 发现 id=23 误分类             │
    ├─ 分析根因 + 修改提示词 ───────→│
    │                                ├─ 重新执行分类
    │←───────────────── 返回结果 ────┤
    │                                │
    ├─ 确认准确率 100%               │
    └─ 输出 README                   │
```
